# 远程抓包 · Capture Desk

中文 Windows 桌面工具。通过 SSH 控制 Linux 的 tcpdump，同时管理最多 10 台服务器；停止后自动下载并校验 pcap，可用 Wireshark 打开。

## 运行

解压发布包，打开 `RemoteCaptureDesk/RemoteCaptureDesk.exe`；本项目内的最终程序位于 `dist/v1.0.0/RemoteCaptureDesk/RemoteCaptureDesk.exe`。**移动或分发时请保留整个 RemoteCaptureDesk 文件夹**，其中的 `_internal` 是运行依赖；目标电脑无需安装 Python。

1. 添加服务器，填写 IP、SSH 端口、用户名，选择密码或私钥登录。
2. 选择直接执行、免密 sudo 或密码 sudo。密码默认只在本次程序运行中保留；勾选“安全记住”后存入 Windows 凭据管理器。取消勾选并保存会移除之前记住的该服务器凭据。
3. 点击“测试连接并读取网卡”。首次连接核对主机指纹后选择网卡，默认 `any`；双击服务器行可以修改配置和凭据。
4. 勾选服务器，设置时长、大小、可选包数和过滤条件。表单过滤与高级 BPF 模式互斥。
5. 点击“预览并开始抓包”，检查每台服务器的实际过滤条件后开始。连接失败的服务器会列明原因，可只启动成功的服务器。
6. 点击“停止所选”或“停止全部”，或等待任一保护上限触发。文件关闭后自动下载，校验大小和 SHA-256 后标记完成。
7. 选择任务，点击“Wireshark 打开”或“打开目录”。Wireshark 未安装或未找到时，可自行安装后选择其程序路径。

## 服务器要求

- 可从本机直接访问 Linux SSH，支持 SFTP；网络连通之外，还需要有效账号和抓包权限。
- 已安装 tcpdump，权限环境中的 PATH 可以找到它。第一版不安装软件或修改 sudo 策略。
- 可用的 `sh`、`nohup`、`awk`、`stat`、`date`、`sleep`、`kill`、`sha256sum`、`df`、`tr`、`grep`、`readlink`、`id`、`chmod`、`mkdir`、`mv`、`cat` 及 Linux `/proc`。使用标准 Linux 工具选项，不保证精简 BusyBox 系统兼容。
- 远端临时目录默认 `/tmp`，必须存在且 SSH 用户可写；启动时要求可用空间至少为大小阈值加 64 MiB。
- sudo 模式通过 `sudo ... sh -c` 执行预检和一次性监督脚本。**只允许 sudo tcpdump 的受限规则不足以运行此版本**；不支持 `requiretty`。失败时将显示 sudo 的具体错误。
- 不支持跳板机、交互式堡垒机、交互式 MFA 或实时流式抓包。

## 保护与恢复

- 默认最长 600 秒、每台 500 MiB、完整报文、包数不限。时长必须为 1–86400 秒，大小阈值为 1–102400 MiB，不能取消所有保护。
- 服务器约每秒检查停止条件；大小阈值并非磁盘硬配额，高流量下会超出阈值。多个任务的磁盘预检不构成空间预留，磁盘被其他程序占用时抓包仍可能失败。
- 默认排除本机与目标服务器之间该 SSH 端口的 TCP 流量，涵盖工具重连，也可能排除同一客户端的其他 SSH 会话。若需分析 SSH 流量，可取消此选项。
- 远端为每个任务创建独立的 `capturedesk-<任务ID>` 目录，保留监督脚本、状态、tcpdump 日志和 `capture.pcap`。发送停止信号前必须核验 PID、进程启动标识以及其为监督脚本直接子进程；`/proc` 权限允许时还会核验可执行文件和输出文件路径。不使用 `killall` 或 `pkill`。
- 保留 tcpdump 默认降权行为，由监督脚本预先打开抓包输出文件，兼容该用户对任务目录没有访问权限的情况；SSH 用户仍可通过 SFTP 读取结果。
- 本机断网/退出后，远端继续抓包，至保护上限停止。工具重新打开后，选择“状态未知”的任务，点击“恢复连接 / 重试下载”。恢复使用任务原始服务器地址与认证配置；修改服务器地址不改变历史任务目标。
- 非记住的密码重启后需要重新输入；私钥文件仍须存在，带口令的私钥请在服务器配置中补充口令后恢复。
- 发现失联时显示“状态未知”，不会误报抓包已停止，也不会自动启动替代抓包。恢复连接后可以停止、读取最终状态并下载。
- 下载失败保留 `.pcap.part` 和远端原文件，重试从头下载；仅成功校验的文件使用 `.pcap` 扩展名。已存在且内容不匹配的本地文件不会被覆盖。
- tcpdump 异常退出但仍有有效文件时，尝试下载并标注“完成（抓包异常）”，请查看详情。服务器重启、监督进程被外部终止或存储设备故障，可能使状态无法自动恢复；此时应检查任务目录和服务器日志。
- 工具**不会自动删除远端文件，也不提供批量删除功能**。请根据实际空间使用情况，人工检查并逐个清理明确的任务文件。
- Windows 首次运行未经代码签名的自建程序可能出现系统提示；此交付不包含代码签名证书。

## 本地数据

- 配置、历史：`%LOCALAPPDATA%/RemoteCaptureDesk/state.json`。
- 已信任主机：同目录的 `known_hosts`。主机指纹变化会阻止连接，应先与管理员核实，确认后再人工编辑对应主机记录。
- 凭据：Windows 凭据管理器，服务名 `RemoteCaptureDesk`；不会写入 JSON、源码或测试报告。
- 默认下载路径：Windows 文档目录下的“远程抓包”，再按批次、服务器名分类；文件使用唯一任务 ID 命名。
- 同一个数据目录限制运行一个应用实例；可用 `--data-dir <绝对目录>` 指定独立测试数据。

## 从源码运行与构建

需要 Windows 10/11 x64 和 Python 3.12：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe -m pytest -q
.\scripts\build.ps1
```

GUI 依赖使用 `PySide6-Essentials`，包含本程序所需的 Qt Widgets；不下载未使用的 WebEngine 组件。使用 PyInstaller 目录模式打包，避免启动时解压大型单文件。

`requirements-lock.txt` 固定了本次 Windows x64 / Python 3.12 构建的全部依赖与 wheel 校验值，可替代 `requirements-dev.txt` 进行精确重建。构建脚本使用专用 spec，避免将构建环境中不兼容的 ICU 库和系统 API shim 带入发布包。输出目录若已存在，脚本会停止；请用 `-OutputRoot` 指定新目录，不会批量删除旧版本。

打包程序如在启动阶段失败，会在数据目录生成 `startup-error.txt`，用于定位缺失依赖。

## 测试

`tests/` 覆盖过滤条件、输入校验、凭据脱敏、主机指纹、下载完整性/冲突/中断、任务隔离和界面恢复。实际服务器测试脚本位于 `scripts/integration.py`，仅抓取回环 ICMP，自建短时且有大小上限的任务；不会清理远端文件或修改系统配置。密码通过临时进程环境变量 `CAPTURE_TEST_PASSWORD` 传入，脚本不保存它。

详见 `TEST_REPORT.md`，以其中实际记录为准；模拟测试通过不等同于所有服务器环境均已验证。
